# Coolify temp static site

Restore or publish a temporary static mock on the Coolify host behind Traefik, when the domain answers 503 and no Coolify app owns it.

## Steps

1. Open root SSH with the shared key: `ssh -i ~/.openclaw/workspace/coolify-server-access/ssh_key -o BatchMode=yes root@10.0.0.3`. If the key is missing, ask the shelldon main agent via `sessions_send` for the current Coolify root path instead of guessing users or passwords; confirm with `sessions_history` that it answered.
2. Copy the static files directly to the destination: `mkdir -p /root/<name>/` once, then `scp -i KEY local/index.html root@10.0.0.3:/root/<name>/index.html` (subdirs likewise); no /tmp staging is needed since scp writes the destination path.
3. Check for an existing container first with `docker ps -a --filter "name=<name>"`: when it exists but is stopped, run `docker start <name>` and skip to verification, since Traefik picks the revived backend up without new labels. Otherwise run a new container on the `coolify` network with Traefik labels, port 80, image `nginx:stable-alpine`, `--restart unless-stopped`, volume `/root/<name>:/usr/share/nginx/html:ro`. Router rule labels must read `Host(`domain`) && PathPrefix(`/`)`.
4. Escape only the backticks in the router rules as \` because the remote command runs inside single quotes and bare backticks execute as command substitution; never escape `&`, since a stray backslash before `&` makes Traefik reject the rule with `illegal character U+005C`; check the applied labels with `docker inspect <name>` and re-create when a rule lacks backticks or contains a backslash, then confirm with `docker logs coolify-proxy` showing no rule-parse error, since the container reports Up even with broken routing.
5. To publish updated content, copy the new files into `/root/<name>/` (same sub-paths) — no container restart is needed because nginx serves the mounted volume live; then re-verify per step 6. When the page contains inline `<script>`, extract the script body and syntax-check it with node (`new (require('vm').Script)(code)`) before copying, since a broken script silently disables checkmarks and stored state while the page still serves HTTP 200. When appending another IIFE before `</script>`, keep the existing `})();` terminator intact and add `(function(){...})();` after it, since replacing the terminator with `})(function(){` fuses both blocks into a single call expression — the fused form still parses, so the syntax check passes while the second block never runs and throws a TypeError at the end; treat zero `pageerror` events in the headless run as the real check.
6. Verify with a `web_fetch` of the public URL and require HTTP 200 plus the expected page title; when the title is unchanged from the previous version, also require one version-specific content marker string from the fetched text (for example a new heading or label the old page lacks), since title-only verification passes on stale or cached content; when the result carries `cached:true` or an older `fetchedAt`, repeat the fetch with an extra dummy query parameter before trusting it. HTTP 200 alone never counts as verified, since broken styling (for example a link-color rule overriding button text color) still serves 200.
7. Render and look at the page before reporting done: resolve the headless binary with `find ~/.cache/ms-playwright -name chrome-headless-shell -type f | head -1`, then screenshot with `--headless --disable-gpu --no-sandbox --hide-scrollbars --window-size=1280,1100 --force-device-scale-factor=2 --screenshot=/tmp/<name>-top.png https://<domain>/`, plus one full-page shot (`--window-size=1280,5200`) and one mobile shot (`--window-size=390,3400`). Copy the PNGs into the workspace first because `view_image` refuses paths outside allowed directories, then inspect each shot and confirm button labels are visible, contrast holds, and nothing overlaps; fix and re-shoot until clean. When the cause of an overlap or overflow is unclear, or to prove a truncation or shift fix before deploying, measure the width chain per references/headless-layout-check.md instead of guessing. Keep `docker rm -f <name>` as the documented undo.

## Standing preferences

- Prefer a sub-path (for example `/v2/`) on the existing temp container over replacing the current mock, so the old page keeps working.
- Record the container name and served path in the workspace `AGENTS.md` project notes, never secrets or tokens.
- Do not create a Coolify app entry for a temp mock; the container is intentionally outside the API inventory.
- When the page is a companion checklist that must stay open while the reader follows outbound links, put `target="_blank" rel="noopener"` on every outbound link including styled buttons, since the first click would otherwise navigate the helper away; verify by counting `target="_blank"` occurrences against total `<a ` tags in the served file.
- When links are styled as buttons, give the button selector at least the specificity of content-link rules (for example `a.btn` placed after `.card a`), since a tied-or-weaker button color rule loses and renders button text in link color on the button background.
- Write all reader-facing copy in the repository glossary's canonical domain terms and plain everyday words — never internal test codes, role abbreviations, or jargon like staging — since the reader is a non-technical tester who follows the page alone; verify with a case-insensitive grep for the banned words before uploading.
- Keep a nested local-only git repo in the site dir (branch `main`, no remote); commit the published baseline, then deploy each tweak uncommitted via scp for live review and commit only when the user says go, since tweaks arrive as several small rounds per version.
- When a single-file page's header fills the whole mobile viewport, collapse the intro into the viewport-aware `<details>` from references/mobile-disclosure.md (open on desktop with the summary hidden, closed on small screens until tapped), since the reader must reach content and progress in the first viewport.
- Order overlapping `max-width` media queries so the narrower one comes later in source, since at widths matching both queries the later rule wins regardless of breakpoint width; after editing, confirm the applied computed value headless instead of assuming the narrower query applies.
- Scope component selectors with the child combinator (for example `.meta-row>span` instead of `.meta-row span`), since a nested identical element otherwise inherits the component's own box styling and renders a badge inside a badge.
- Scope localStorage keys with the content version (for example `nils-mvp-<sha>-klar`) and bump them with each release, since persisted checkmarks and parked data from the previous version would otherwise carry over into the new one; verify with grep that no old-version key string remains before deploying.
