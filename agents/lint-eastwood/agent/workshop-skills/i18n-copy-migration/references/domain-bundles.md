# Splitting a single locale file into domain bundles

Use this before a large copy migration when one `<locale>.json` has grown past a few hundred lines.

1. Choose 6-9 domains that match feature ownership and the translation packages, such as `common`, `onboarding`, `organizations`, `settings`, `projects`, `partnerships`, `participations`, `claims`, and `shell`. Include `settings` when user-settings copy has its own package; otherwise the plan needs a new bundle later. Do not create one file per component or per feature; that multiplies files, loaders, and type glue without reducing the client payload.
2. Use `src/messages/<locale>/<domain>.json`, not domain-first: the request loader and type are per locale, and translators work per language. Every domain exists in every supported locale, even when untranslated locales mirror the source copy.
3. Move existing namespaces mechanically and keep shared keys in `common`. Do not change copy in this step; the guard count must stay identical before and after. Deep-compare each old locale object against the merged new object with `assert.deepStrictEqual`, reading the old file via `git show HEAD:<path>`; `JSON.stringify` comparison is order-sensitive and reports false mismatches.
4. Add `src/messages/domains.ts` with the domain list and one `src/messages/<locale>/index.ts` per locale that imports every domain JSON and calls a shared `mergeMessages` helper. Next must see static paths; a dynamic feature path hides files from the bundler.
5. Implement `mergeMessages` with a generic intersection return type and reject duplicate top-level namespaces. Do not use a plain object spread: it silently overwrites duplicates. Import the helper through the repo alias (`@/messages/merge`) when the linter rejects parent-relative imports, and add a unit test for merge plus duplicate rejection; the request shape test does not exercise the helper.
6. Rebuild the next-intl type in `src/messages/en/index.ts`: widen string literals with `type Widen<T> = T extends string ? string : { [K in keyof T]: Widen<T[K]> }`, export `Messages = Widen<typeof messages>`, point `global.d.ts` at it, and type the per-locale loader map in `request.ts` as `Record<LanguageCode, () => Promise<{ default: Messages }>>`. Literal English values otherwise reject translated values.
7. Narrow the locale before indexing the loader map: `const supportedLocale = isSupportedLocale(locale) ? locale : DEFAULT_LANGUAGE`. A mutable `let` narrowed by an `if` can still fail under TypeScript.
8. Update every `@/messages/<locale>.json` import to `@/messages/<locale>`, delete the old JSON files, and filter the request test's file enumeration to `.json` because each locale directory also contains `index.ts`.
9. Rewrite the request test that assumes one file per locale: every domain bundle exists in every locale, shapes and placeholders match, the merged tree matches the sum, and the default-locale fallback works.
10. Confirm `resolveJsonModule` is enabled, then run type-check, request tests, and focused suites. When `next typegen` reports a route in `.next/dev/types/validator.ts` that no longer exists, remove the generated `dev/types` directory and regenerate before changing application code.

11. If the app serves unprefixed routes outside `[locale]`, add a default-locale provider at the root for the shell catalog and keep the localized provider in `[locale]`. If a root page calls `getTranslations` and is proxy-rewritten to a localized route, make its fallback blocking instead of statically prerendered (Next.js: `export const instant = false`) so build-time prerender does not run outside provider context.

Splitting files improves ownership and merge conflicts. It does not shrink the client bundle while one `NextIntlClientProvider` receives the merged tree.
