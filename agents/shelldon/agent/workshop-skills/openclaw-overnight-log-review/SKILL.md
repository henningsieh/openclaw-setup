# OpenClaw overnight log review

1. Define the requested time window in the user's local timezone and inspect `openclaw config get logging` to locate the active file and its rotation size. List that directory with `ls -lah` and inspect `head -1` and `tail -1` of each current and rotated file to establish actual retained timestamps, because a recent log tail does not establish overnight coverage.
2. If retention is unexpectedly short, run `rg -c 'running event-loop-health' <rotated-file>` and `wc -l <rotated-file>` and compare timestamps and file sizes, because high-volume trace messages can rotate useful history rapidly. Report the observed counts and window without assuming why trace logging was enabled.
3. Check the system service with `systemctl show openclaw-gateway.service -p ActiveState -p ActiveEnterTimestamp -p NRestarts --no-pager` and request the relevant interval with `journalctl -u openclaw-gateway.service --since '<start>' --until '<end>' --no-pager -o short-iso`; inspect permission notices and `test -r /var/log/syslog`, because an empty restricted journal is not proof that system logs do not exist. Name any access limitation and do not claim the journal is empty globally.
4. Inspect automation history independently with `openclaw cron runs --all --limit 200 --json` and filter `.entries` by `runAtIso` within the local time window, for example `jq -r '.entries[] | select(.runAtIso >= "<start-ISO>" and .runAtIso < "<end-ISO>") | [.runAtIso,.jobName,.status,(.error // ""),(.summary // "")] | @tsv'`; paginate using `nextOffset` and `--offset` if the window is not fully covered. Report run status and delivery separately, distinguish expected skips from errors, and check dates in cached diagnostic summaries before treating them as fresh measurements.
5. If a relevant backup exists, inspect archive contents read-only with `tar -tzf '<archive>' | grep '/logs/gateway/'` and wait for the listing to finish, because a backup of state need not include gateway logs. Do not extract or restore an archive just to verify whether the log path exists.
6. If the user requests a logging fix and trace-level volume is driving rotation, inspect `openclaw config get logging`, then validate and apply `openclaw config set logging.level '"info"' --strict-json --dry-run` followed by the same command without `--dry-run`, preserving the existing file and rotation settings. Verify `openclaw config get logging` and inspect newly appended records with `tail -n 5000 <log-file> | jq -r 'select(.time >= "<change-local-ISO>") | [._meta.logLevelName,.message] | @tsv'`, because accepted configuration alone does not prove the noisy stream stopped; distinguish residual worker trace from the original flood. Leave existing rotated logs intact unless deletion is explicitly authorized.
7. Summarize concrete events with local times and source, state whether coverage is complete, and distinguish missing rotated files from inaccessible journal or syslog. Keep a review read-only unless the user also requests a fix.
