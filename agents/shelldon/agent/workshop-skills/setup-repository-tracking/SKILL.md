# Setup repository tracking

1. Inspect the repository before editing: run `git rev-parse --show-toplevel`, read its `AGENTS.md` and tracking documentation, then run `git status --short`, `git diff --cached --stat`, `git diff --stat`, and `git ls-files -s`. Preserve pre-existing staged changes separately because they must not leak into the cleanup commit. Inspect nested repositories and symlinks without following them recursively.

2. Define the tracking boundary by role, not by directory name alone. Keep configuration without credentials, maintained documentation, plugins, scripts, tests, agent definitions, and requested skill source. Exclude user profiles, memories, project output, reports, databases, media, caches, backups, credentials, sandbox state, and generated installation trees. Include skill source wherever it actually lives, including `skills/`, workspace `skills/`, workspace `.agents/skills/`, and agent `workshop-skills/`; exclude undo archives and generated skill state. Keep a nested repository out of the parent index unless the owner explicitly requests a submodule. Do not infer that a directory is disposable merely because it is excluded from Git.

3. Merge `.gitignore` rules with existing policy. For a mixed setup/state directory, use a root allowlist (`/*` followed by explicit `!/path/` exceptions), then private-by-default workspace rules with deliberate source exceptions. Unignore every ancestor before a descendant, because Git does not traverse ignored parents. Put generated-file rules such as `node_modules/`, `__pycache__/`, `*.sqlite*`, `*.db`, `.env`, and credential backup variants after source exceptions so an allowed source tree cannot admit runtime secrets. Test representative real and future paths with `git check-ignore --no-index -q <path>`; require private paths to return 0 and retained source to return 1. Retain the repository's approved configuration snapshots rather than broadening or narrowing that policy silently.

4. Remove newly ignored tracked paths from the index only. Preview with `git ls-files -ci --exclude-standard`. For filenames with spaces, use NUL-delimited input: `git ls-files -ci --exclude-standard -z | git rm --cached --ignore-unmatch --pathspec-from-file=- --pathspec-file-nul`. Capture hashes of existing working files before this step and compare them afterward, because index deletion must not delete or rewrite personal files. Count already absent files separately. Never run `git clean`, delete workspaces, or rewrite history as part of ignore cleanup; older commits retain the excluded content until a separately authorized history purge.

5. Update the repository's tracking documentation in the same change, because the ignore rules and their written contract must agree. Briefly show what stays, what is excluded, how many index entries changed, and that working files remain before making the requested commits. Follow an explicit approval checkpoint if one was requested; otherwise proceed after the preview.

6. Inspect candidate content without disclosing credentials. Scan the files selected for tracking against locally available credential values in memory and print only matching paths, never values or raw auth-store payloads. Inspect credential-shaped fields and generated configuration snapshots separately; a scan against known values is not proof that no other secret exists. Inspect skill symlink targets and their source inclusion so tracked links do not point to missing ignored sources. Do not execute a specialist skill merely because its files are being committed.

7. Split commits by actual purpose using explicit `git add <paths>` and the repository's commit-message convention: tracking/index cleanup, configuration and matching documentation, operational workflows, skill sources, and agent definitions when those are distinct changes. Before every `git commit`, inspect `git status --short`, `git diff --cached --stat`, and the staged diff, then run `git diff --cached --check` plus relevant syntax checks. Stage only the relevant hunks of shared documents; use `git add -p <file>` or the exact index-blob technique in `references/split-document-staging.md`. Preserve the working file and other staged changes. Keep third-party source untouched except a necessary reviewed formatting fix.

8. Verify completion with `git status --porcelain`, `git ls-files -ci --exclude-standard`, `git log -<count> --format="%h %s"`, and `git diff HEAD~<count>..HEAD --check`. Require no accidentally tracked private profiles/databases or embedded gitlinks, verify retained skill source is present, and recheck preserved working files. Report commit hashes and any remaining dirty paths honestly. Keep commits local when requested; do not push or erase historical personal data without separate authorization.
