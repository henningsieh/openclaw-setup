# Repair Memory

1. **Identify the failing corpus and agent first.** Read the actual `memory_search` result (especially `corpus`, `disabled`, `unavailable`, `corpora` outcomes and timeout warnings). Compare `openclaw memory status --agent <id> --deep --json`, `openclaw config get memory --json`, the agent's `agents.entries.<id>.memory.search` override, and `plugins.entries.memory-core`. The memory-file index can be healthy while `corpus: "sessions"` is disabled; `wiki` is a compiled supplement, not an extra `memory.search.sources` value. Finish when the missing source, index fault, provider fault, or plugin fault is explicit.

2. **If only session transcript search is disabled**, set `agents.entries.<id>.memory.search.experimental.sessionMemory: true` and `agents.entries.<id>.memory.search.sources: ["memory", "sessions"]` for the affected agent. Preserve inherited provider/fallback and other agents' settings; do not turn on broader cross-conversation recall or widen `tools.sessions.visibility`. Validate together with `openclaw config set --batch-json '[{"path":"agents.entries.<id>.memory.search.experimental.sessionMemory","value":true},{"path":"agents.entries.<id>.memory.search.sources","value":["memory","sessions"]}]' --dry-run` (substitute the agent id); then run the same command without `--dry-run` and read back. Check `openclaw memory status --agent <id> --json` for `sources` and the session source's `eligible` count. Run `openclaw memory status --index --agent <id> --json` to index eligible transcripts; finish when `dirty: false` and session `files/chunks` are present. Do not mistake unrelated memory-file hits for session-search proof.

3. **If embedding/indexing fails**, keep a ready remote provider. Only for a failed/unavailable or quota-exhausted remote endpoint, read `references/local-embedding-fallback.md` and complete that branch; never silently settle for FTS-only. For `ENOSPC`, read `references/disk-pressure-recovery.md` before retrying. If a provider change needs a restart, let active work drain and verify the service returns to `active/running` before indexing. After an interrupted command, inspect current state before repeating it. Use `openclaw memory status --index --agent <id>` (or `openclaw memory index --force --agent <id>` when rebuilding is required). Finish when files are indexed, `dirty: false`, semantic vectors are ready, and the embedding identity matches the intended provider.

4. **If Memory Dreaming names the model-override trust guard**, set `plugins.entries.memory-core.subagent.allowModelOverride` to `true` and read it back. Do not grant broader permissions or change the Dreaming model. Find the managed job `memory-core:memory-dreaming-promotion`, run it once when safe, and require `lastRunStatus: ok`, `memory-core: dreaming promotion complete` in Gateway logs, diary entries, and no new model-override rejection. If a CLI wait times out, inspect job state and logs before retrying; it may have finished asynchronously. Do not trigger Dreaming for an unrelated search repair.

5. **Prove the requested search path, not just config.** For memory-file search, run `openclaw memory search --agent <id> --max-results 3 "<known term>"`. For `sessions`, have the target agent call `memory_search` with `corpus: "sessions"` and a term known from one of its sessions; require no disabled/unavailable flag and a session hit. If the request includes `wiki` or `all`, test those corpora as the same agent and inspect each corpus outcome, not just nonempty results: `all` may return memory hits while wiki timed out. A wiki-only timeout with a healthy `wiki_status`/`wiki_search` is a performance/timeout issue, not proof the source is disabled; rerun the individual corpus without concurrent indexing, then report any remaining partial result. Finish only when each requested corpus succeeds or its exact remaining blocker is reported.
