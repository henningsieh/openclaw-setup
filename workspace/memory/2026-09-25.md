## Browser and web-search setup fix (owner request)

Two independent failures, both now resolved and verified live.

**1. Browser could not start** — no supported Chromium binary on the host
(`browser doctor`: `No Chromium executable detected`, `executablePath=null`).

- Installed Google Chrome 154.0.8037.57 under `$HOME/.local/opt/google-chrome/`,
  extracted from Google's `.deb`. Needed the non-root route because this session
  cannot `sudo` and host elevation is disabled for webchat.
- Set `browser.executablePath` to
  `/home/shelldon/.local/opt/google-chrome/current/opt/google/chrome/chrome`.
- Set `browser.noSandbox=true` (owner chose this). Reason: the host blocks
  unprivileged user namespaces and the extracted `chrome-sandbox` is not
  root-owned, so Chrome aborts with the SUID-sandbox error. The clean alternative
  is a root `apt-get install` of the Chrome package, which keeps the sandbox.
- Verified after the gateway restart: CDP reachable, headless, and a live
  retailer product page was read successfully.

**2. `web_search` failing** — DuckDuckGo served anti-bot challenges to this host
(its own page asks to "select all squares containing a duck"). That integration is
unofficial HTML scraping, so it is not a misconfiguration; nothing local could fix it.

- Owner chose Gemini (Google Search grounding) and supplied `GEMINI_API_KEY`.
- Set `tools.web.search.provider: "gemini"`.
- Root cause found for the first 429s: OpenClaw's Gemini search default model is
  `gemini-3.6-flash`, which is **quota-exhausted** on this key, while
  `gemini-2.5-flash` works. Pinned
  `plugins.entries.google.config.webSearch.model: "gemini-2.5-flash"`.
- The model pin only takes effect through a plugin reload, and the reload was
  refused repeatedly with `Plugin google still has active retained work`. The owner
  restarted the gateway; after that, search worked.
- Verified live: `web_search` returned `kind: "answer"` from provider `gemini`
  with 4 grounded citations.

**Provider id note:** OpenClaw's Gemini search provider id is `gemini`, not `google`.
The `google` plugin id is what holds `plugins.entries.google.config.webSearch`.

## Lessons

- `browser.noSandbox=true` is a real isolation trade-off; prefer the root package
  install when sudo is available.
- A search provider switch is not live until the plugin reload succeeds. A stuck
  `still has active retained work` guard that never clears needs a restart.
- Do not stop other search-provider plugins from a turn that itself holds the plugin;
  the reload guard will refuse.
