# 2026-09-29 — Daily Notes

## Markus Lanz guest list — silent parser breakage, fixed
<!-- project: github.com/henningsieh/openclaw-setup -->
- Symptom: no guest list on Tue 29.09. The cron itself was healthy — 12 runs,
  last 17:30 CEST, `lastRunStatus: ok`, `consecutiveErrors: 0`. The script exits
  0 with no stdout when it finds nothing, so a parse failure is indistinguishable
  from "not published yet" in the run history.
- **Cause: not the layout.** The script's `mit:` anchor still matched. Since the
  production company's update, each line is `Name, Role / <~210-char description>`
  and the old guard `title.length < 150` rejected every guest. The description is
  not metadata and was only ever needed to fail the length check.
- **Two fixes in `parseGuests()`** (`~/.openclaw/workspace/lanz_cron/lanz-guests.js`):
  1. cut the role at the first `/`; keep only what precedes it
  2. normalise `\u00a0` before splitting — the page uses a non-breaking space
     after the slash, so a `' / '` match silently misses. **The first fix
     attempt used `' / '` and passed zero guests in test; do not repeat that.**
- Proof: `node lanz-guests.js --test <fixture>` returned 0 before and 4 after
  (Hubertus Heil, Marc Felix Serrao, Ursula Weidenfeld, Susanne Petersohn).
  Forced cron run at 19:47 delivered and wrote the show to SQLite.
- Schedule widened `*/30 11-17` → **`*/30 11-19 * * 2,3,4` Europe/Berlin**. The
  29.09. show aired 22:45, outside the old window entirely; 19:00 is the latest
  practical bound because the list is published before airtime, not at airtime.
- Owner decision: keep fernsehmacher.de as the source. It is Lanz's production
  company, i.e. the authoritative publisher, despite being a WordPress blog that
  can be rebuilt at any time. Switching to a secondary source was rejected.
- **Known design weakness, not yet fixed:** any future format change reproduces
  this as a silent no-op. A health check that alerts after N consecutive runs
  with zero guests would turn a missing message into a visible failure. Offered
  to the owner, not built.

### Lesson: I invented a data gap that did not exist
I reported a "5-day gap" in the guest DB and told the owner his Wednesday and
Thursday messages were lost. **Both were false.** The show airs only Tuesday to
Thursday, so Thu 24.09. was the last show day before the weekend and Fr–Mon are
correctly absent from the table. Correct timeline: 24.09. 12:00 last successful
fetch → 25.–28.09. no show, nothing to fetch → 29.09. first show day, parser
returned 0 → 19:47 fixed.
The underlying defect was real and verified; only my reading of the calendar was
wrong. **Check the show schedule before reading absence as loss** — a sparse
table is the expected shape, not a symptom.
