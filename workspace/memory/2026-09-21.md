## SECRETS: ONE location — ~/.openclaw/.env (2026-09-21 14:00)
Rule, decided by Human: exactly ONE secrets file = `~/.openclaw/.env` (0600, gitignored).
No protected store usage for env secrets. Rationale: `.env` is the only location that
serves BOTH consumers — the gateway loads it into process env (config can use `${VAR}`),
and agent exec subprocesses inherit it. Protected-store `secret` values are never injected
into subprocesses, so they cannot serve exec.

- Moved into `.env`: `OPENROUTER_API_KEY`, `GEMINI_API_KEY`, `GROCY_API_KEY` (values copied
  store→file via a throwaway DB copy in /tmp; never printed).
- Removed the 3 team store entries → `openclaw secrets store list` = "No team secret store entries".
- `.env` now holds 5 keys: HCLOUD_TOKEN, COOLIFY_API_TOKEN, OPENROUTER_API_KEY, GEMINI_API_KEY, GROCY_API_KEY.
- Direct rule for the future: CLI/exec credential → `~/.openclaw/.env`; config credential →
  `${VAR}` reference to that same file. Never two plaintext copies.
- Note: I erroneously routed those 3 into the protected store earlier today; that created the
  duplicate location. Corrected here.
- Do NOT touch `github-connection` (scope `identity/gateway-owner`) — that is the Control UI
  GitHub identity store entry, not an env secret.
